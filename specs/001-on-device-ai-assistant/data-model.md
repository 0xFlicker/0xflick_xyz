# Data Model: On-Device AI Assistant

**Feature**: `001-on-device-ai-assistant`  
**Date**: 2026-08-20  
**Database**: `flick-assistant`, schema version 1

## Design Rules

- IndexedDB is authoritative while durable mode is healthy. The page-lifetime memory repository uses the same records, validation, ordering, and mutation results.
- Every identifier is a locally generated UUID. No message content is placed in an identifier, URL, index key, lock name, log, or analytics event.
- A turn is the unit that permanently relates one user prompt to its one assistant response. Transcript order is turn order `(promptCreatedAt, turnId)`, then user before assistant within the turn.
- Submitted user content is durable before generation starts. Streaming assistant content is checkpointed and its final status is committed atomically with the turn.
- Terminal turns are immutable. Retry creates a new turn; it does not overwrite prior prompt or response content.
- A model session is an ephemeral runtime resource, never persisted data. One session may be retained for the selected chat while its persisted prompt inputs still match; otherwise it is destroyed and reconstructed from the records below.

## Stored Entities

### AppMeta

Singleton non-content coordination record.

| Field | Type | Rules |
|-------|------|-------|
| `key` | `"app"` | Primary key |
| `datasetEpoch` | integer | Starts at 1; incremented by Clear all; every async mutation must compare its captured epoch before writing |
| `activeSessionId` | UUID or `null` | Last active saved session; set to `null` for the blank draft or when no saved sessions remain |
| `persistenceRequestedAt` | timestamp or `null` | Records the one best-effort `navigator.storage.persist()` request; denial is not failure |
| `updatedAt` | timestamp | Last coordination change |

`AppMeta` survives Clear all only as empty coordination state with a new epoch. It contains no conversation or preference content.

### AssistantSession

One saved conversation. A blank New Chat is ephemeral and does not consume the 100-session limit until its first valid prompt is committed.

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key; stable for session lifetime |
| `epoch` | integer | Must equal the current `AppMeta.datasetEpoch` |
| `title` | string | Deterministically derived from the first prompt; never generated by the model |
| `titleSourceTurnId` | UUID | The first committed turn |
| `createdAt` | timestamp | Set once |
| `updatedAt` | timestamp | Advances when a prompt is accepted or a turn becomes terminal; session lists sort descending by this value, then descending by `id` |
| `historyRevision` | integer | Increments when a turn becomes terminal; used for compaction compare-and-swap |

Title derivation trims and collapses whitespace, removes leading Markdown decoration, takes at most 48 Unicode code points at the nearest preceding word boundary, and appends an ellipsis when truncated. Duplicate titles are valid because identity and recency remain visible.

### ConversationTurn

The queue, concurrency, and prompt/response association record.

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key and deterministic ordering tie-breaker |
| `sessionId` | UUID | Required parent |
| `epoch` | integer | Captured at submission and checked on every write |
| `promptCreatedAt` | timestamp | Set at accepted submission; primary chronological sort key |
| `userMessageId` | UUID | Required one-to-one user message |
| `assistantMessageId` | UUID | Required one-to-one assistant placeholder/message |
| `status` | enum | `queued`, `generating`, `completed`, `interrupted`, or `failed` |
| `generationAttemptId` | UUID or `null` | Set only while generating; prevents a stale producer from checkpointing over a newer transition |
| `startedAt` | timestamp or `null` | First transition to generating |
| `completedAt` | timestamp or `null` | Any terminal transition time |
| `interruptionReason` | enum or `null` | `visitor`, `owner_closed`, `session_switched`, `deleted`, `cleared`, or `model_unavailable` |
| `failureCode` | stable error code or `null` | Product-level code from the model or persistence contracts; never raw prompt content |

Exactly one turn per session may be `generating`. Any number may be `queued`. When a window obtains the session's exclusive Web Lock, it first converts an orphaned `generating` turn to `interrupted/owner_closed`, then selects the earliest queued turn by `(promptCreatedAt, id)`.

### Message

Visible transcript content.

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key |
| `sessionId` | UUID | Required parent; duplicated for bounded session queries |
| `turnId` | UUID | Required parent turn |
| `role` | enum | `user` or `assistant` |
| `text` | string | User text or streamed assistant text; not indexed |
| `status` | enum | User messages are `completed`; assistant messages are `pending`, `streaming`, `completed`, `interrupted`, or `failed` |
| `createdAt` | timestamp | User time is submission time; assistant placeholder uses the same time and renders second by role |
| `updatedAt` | timestamp | Last stream checkpoint or terminal transition |

There is exactly one user message and one assistant message per turn. An interrupted or failed assistant message may contain partial text, which remains visible and is not represented to the model as a completed answer during reconstruction.

### ContextState

The persisted representation used to reconstruct one session's model context. It never replaces or deletes transcript messages.

| Field | Type | Rules |
|-------|------|-------|
| `sessionId` | UUID | Primary key |
| `epoch` | integer | Must match session and dataset epoch |
| `state` | enum | `fresh`, `warning`, `compacted`, `overflowed`, or `unknown` |
| `summaryText` | string or `null` | Model-produced representation of older complete turns; not indexed |
| `summarizedThroughTurnId` | UUID or `null` | Last turn covered by `summaryText` in transcript order |
| `directFromTurnId` | UUID or `null` | First recent completed turn included directly after the summary |
| `contextUsage` | number or `null` | Last reported usage units |
| `contextWindow` | number or `null` | Capacity corresponding to `contextUsage` |
| `promptVersion` | integer | Version of the fixed prompt/compaction format used to construct this state |
| `sourceHistoryRevision` | integer | Session revision summarized; candidate commits only when this still matches |
| `personalityRevision` | integer | Global setting revision used when replacement context was validated |
| `compactedAt` | timestamp or `null` | Last successful compaction |
| `overflowedAt` | timestamp or `null` | Last browser-reported automatic context overflow |

Usage percentage is derived only when both measured values are finite and `contextWindow > 0`. Otherwise the visitor-facing state is `unknown`. `compacting` belongs to ephemeral model activity rather than this record, so an interrupted attempt never replaces the last committed context.

### PersonalitySetting

Singleton global preference.

| Field | Type | Rules |
|-------|------|-------|
| `key` | `"personality"` | Primary key |
| `text` | string | Blank by default; maximum 1,000 Unicode code points |
| `revision` | integer | Increments on each successful save, including clearing the field |
| `updatedAt` | timestamp | Last successful save |

The preference applies only when constructing subsequent model input. It never mutates stored transcript content and is always placed after non-overridable fixed guidance.

### SessionTombstone

Deletion race guard; contains no user content.

| Field | Type | Rules |
|-------|------|-------|
| `sessionId` | UUID | Primary key within an epoch |
| `epoch` | integer | Epoch in which deletion occurred |
| `deletedAt` | timestamp | Deletion commit time |

A mutation may write session content only when its captured epoch equals `AppMeta.datasetEpoch` and no matching tombstone exists. Clear all advances the epoch and clears old tombstones because the epoch itself invalidates all older work.

## Ephemeral State

These values are never persisted as product data:

- The blank draft session and unsent composer text.
- At most one idle retained `LanguageModel` instance for the selected chat, its non-content revision identity, active abort controllers, streams, and progress monitors.
- Per-window identifier and the current Web Lock ownership.
- Model availability/preparation state and measured download progress.
- Clipboard success, dialog focus targets, scroll-follow state, and expanded panels.
- Temporary repository selection for the current visit. Reload always attempts durable storage again.

The retained runtime identity contains only the selected session ID, history revision, fixed prompt version, personality revision, and compacted-context range/timestamp fields. It contains no prompt, response, personality, or summary text. A successful turn advances the retained identity to the committed history revision. Any mismatch, interrupted or failed turn, session switch, destructive action, or runtime failure destroys the native session before later reconstruction.

## Relationships and Indexes

```text
AppMeta 1 ─── current dataset epoch ─── * AssistantSession
AssistantSession 1 ─── * ConversationTurn
ConversationTurn 1 ─── 1 user Message
ConversationTurn 1 ─── 1 assistant Message
AssistantSession 1 ─── 0..1 ContextState
AssistantSession 1 ─── 0..1 SessionTombstone (after deletion only)
PersonalitySetting 1 ─── applies globally to future model input
```

Dexie schema indexes only coordination fields:

```text
meta:          key
sessions:      id, epoch, [epoch+updatedAt]
turns:         id, sessionId, [sessionId+status], [sessionId+promptCreatedAt]
messages:      id, turnId, sessionId, [sessionId+createdAt]
contextStates: sessionId, epoch
settings:      key
tombstones:    sessionId, epoch, [epoch+sessionId]
```

Prompt, response, title, personality, and summary text are deliberately not indexed.

## State Transitions

### Turn

```text
queued ── lock acquired ──> generating ── stream closes ──> completed
  │                              │
  │ visitor stops queued turn    ├── abort / owner lost ──> interrupted
  └────────────────────────────> interrupted
                                 └── model/context failure ──> failed
```

Terminal states do not transition. A race between stop and natural completion is resolved by the first valid terminal transaction for the current `generationAttemptId`; the later writer observes a terminal record and performs no mutation.

### Assistant Message

```text
pending ──> streaming ──> completed
   │            ├───────> interrupted
   │            └───────> failed
   ├────────────────────> interrupted
   └────────────────────> failed
```

The repository may checkpoint streaming text no more often than every 500 ms and must flush once on a terminal transition. A reload can therefore recover useful partial output without treating it as completed context.

### Context

```text
unknown ── valid measurement ──> fresh
fresh ── usage >= 75% ──> warning
fresh/warning/compacted ── compact request ──> ephemeral compacting work
ephemeral compacting work ── replacement validated + commit ──> compacted
ephemeral compacting work ── failure ──> previous committed state + visible error
any measured state ── contextoverflow ──> overflowed
overflowed ── successful rebuild ──> compacted
```

The 75% warning is inclusive. Before generation, projected usage at or above 80% triggers compaction. Automatic browser overflow always wins over a locally calculated percentage and blocks the next turn until rebuild succeeds.

## Atomic Operations

### Accept a prompt

In one transaction:

1. Read `AppMeta` and validate the captured epoch.
2. For a blank draft, count current-epoch sessions and fail with `session_limit` at 100; otherwise create the session and deterministic title.
3. Reject empty/whitespace input and a duplicate submission token.
4. Verify the session exists and has no tombstone.
5. Create the queued turn, completed user message, and pending assistant message.
6. Update `activeSessionId` and session `updatedAt`.

Only after commit may the window seek the session Web Lock.

### Generate a queued turn

Within the exclusive session lock:

1. Re-read durable state and terminalize any orphaned `generating` turn as interrupted.
2. Select the earliest queued turn and atomically assign a new `generationAttemptId`.
3. Reconstruct context from the latest committed state and personality revision.
4. Compact first when required; a candidate summary is not committed until replacement-session creation succeeds.
5. Stream and checkpoint only while epoch, tombstone, turn status, and attempt ID remain valid.
6. Atomically terminalize the turn and assistant message, update session time/revision, and persist measured context.
7. Continue with the next queued turn while the lock remains held and the environment is usable.

### Delete one session

In one transaction, verify the current epoch, insert the tombstone, delete the session's context, messages, turns, and session, and clear or replace `activeSessionId`. Abort local work immediately. Any late writer fails the tombstone guard and cannot resurrect data. Global personality remains unchanged.

### Clear all

Abort local work, then in one durable transaction increment `datasetEpoch`, clear sessions, turns, messages, context states, settings, and tombstones, and set `activeSessionId` to `null`. Keep only the non-content meta record and its one-time persistence-request marker. A UI success state is allowed only after the transaction commits.

If a durable delete or Clear all transaction fails, do not claim completion. Move recoverable current-view content to temporary mode, expose that persistent deletion could not be verified, and offer retry plus browser-site-data instructions.

### Enter temporary mode

On initial open/read failure, initialize a blank memory repository. On a required durable write failure, copy the last coherent in-memory view of the active data into the memory repository, preserve the failed action as not committed, and remain in memory mode for the page lifetime. All subsequent UI actions use only that repository. Reload is the sole automatic durable retry boundary, preventing split-brain histories.

## Validation Invariants

- Session count for the active epoch is never greater than 100; the 101st creation is blocked without deletion.
- Personality saving counts Unicode code points and never replaces the last valid value on an over-limit attempt.
- User prompts contain at least one non-whitespace code point. Capacity fit is decided by `measureContextUsage()`, not by a guessed character limit.
- A session, turn, message, and context record must share the current epoch and valid parent identities.
- Every completed, interrupted, or failed turn has a terminal assistant message with the corresponding visible state.
- A completed turn is included either in the persisted summary range or in direct recent context, never silently in neither when reconstruction claims complete context.
- The fixed system guidance is always first, optional personality guidance is subordinate, and generated summary content is always marked as conversation context rather than instruction.
